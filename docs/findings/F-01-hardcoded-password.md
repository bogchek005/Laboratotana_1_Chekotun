# Finding F-01 — Hardcoded навчальний пароль у tracked HTTP-тесті

**Категорія:** Secret management / source control  
**Пріоритет:** Помірний для локального стенда; підвищується, якщо пароль повторно використаний або репозиторій доступний іншим  
**Стан:** Виправлено в поточному tracked файлі; історичні копії залишаються залишковим ризиком.

## Reproduction

Під час перевірки tracked файлів виконано:

```powershell
git grep -n -I -i -E 'password|passwd|secret|api.?key' -- .
```

У виводі було знайдено `tests/SecureLab.Api.Tests/lab-03-tests.http:4` з буквальним значенням справжнього навчального пароля. Рисунок 82. Сам пароль у цій картці не наводиться.

## Impact

Кожен, хто має доступ до tracked вмісту або старого commit, може прочитати секрет. У локальній лабораторній реальний вплив обмежений навчальними обліковими записами й умовами доступу до репозиторію, однак за повторного використання пароля ризик стає вищим.

## Root cause

Для HTTP-тесту пароль було записано безпосередньо в конфігураційній змінній `@password` замість отримання із середовища запуску.

## Fix

В `tests/SecureLab.Api.Tests/lab-03-tests.http` буквальне значення замінено:

```http
@password = {{$processEnv SeedUsers\_\_Password}}
```

Поточний файл показаний на рисунку 83; історію файлу переглянуто на рисунку 84, виправлення зафіксовано окремим commit на рисунку 85.

## Retest

Переконатися, що `git grep` більше не показує буквального значення у поточному файлі. Показано виправлену змінну, однак повний повторний секрет-скан після commit не зафіксовано окремим доказом. **Статус:** частково підтверджено.

## Positive regression

HTTP-запити збережуть можливість автентифікації при наявності `SeedUsers\_\_Password` у середовищі, з якого запускаються тести. Окремий успішний прогін саме цього HTTP-файлу після виправлення не показано; не оголошувати PASS без перевірки.

## Residual risk

Видалення рядка з актуальної версії **не очищає попередні commits**. Рекомендується змінити навчальний пароль, не використовувати його в інших сервісах і, якщо репозиторій розповсюджувався, погоджено вирішити питання історії Git. Не робити force-push без перевірки гілок і тегів.
