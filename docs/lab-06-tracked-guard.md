# ЛР6 — перевірка tracked paths

**Дата:** 08.11.2026  
**Проєкт:** starter-project  
**Тестовий клас:** SecureLab.Api.Tests.TrackedPathsGuardTests  

## Реалізовані правила

Guard повертає список заборонених шляхів:

* файл із точним ім’ям `.env` заборонено в будь-якому каталозі;
* шлях із закінченням `.local.json` заборонено;
* `.env.example` дозволено за назвою.

Перед перевіркою роздільник `\\\\` замінюється на `/`.
Перевірка закінчення використовує `StringComparison.Ordinal`
і є чутливою до регістру.

Фрагмент умови:

```csharp
return fileName == ".env"
    || normalized.EndsWith(
        ".local.json",
        StringComparison.Ordinal);
```

Перевіряються лише назви шляхів. Вміст файлів не аналізується.
Дозволена назва не є доказом відсутності секретів усередині файла.
Шаблон `.env.example` має містити лише безпечні приклади та placeholders.

## Прогнози та результати наборів

|Набір|Шляхи|Прогноз|Результат після виправлення|
|-|-|-|-|
|P|`infra/.env.example`|Прийнято|Прийнято|
|A|`infra/.env.example`, `config/reports.local.json`|Відхилено|Знайдено `config/reports.local.json`|
|B|`infra/.env.example`|Прийнято|Прийнято|
|Власний контрольний|`infra/.env.example`, `docs/readme.md`|Прийнято|Прийнято|
|Власний граничний|`infra/.env.example`, `config/custom.local.json`|Відхилено|Знайдено `config/custom.local.json`|

Результати відповідають прогнозам. Власний граничний набір показує,
що правило залежить від закінчення шляху, а не від конкретної назви
`reports.local.json`.

## Перевірка до та після виправлення

До доповнення правила guard перевіряв лише точне ім’я `.env`.
Тест A очікував `config/reports.local.json`, але отримав порожній
список. У показаному початковому запуску виконано три тести:
два пройшли, A впав.

Після додавання перевірки `.local.json` набір A правильно
відхиляється. Успішний тест A означає, що guard знайшов очікуване
порушення, а не що набір A дозволений.

## Переходи станів

|Перехід|Зміна|Результат guard|
|-|-|-|
|P → A|Додано `config/reports.local.json`|A відхиляється|
|A → B|Прибрано `config/reports.local.json` зі списку|B приймається|

P і B містять однакові шляхи, але представляють різні стани
навчального сценарію. Самі масиви не створюють Git-комітів.

## Поточний Git index

Тест `CurrentTrackedPaths\_AreAccepted` отримує шляхи командою:

```text
git ls-files -z
```

Шляхи розділяються нульовим символом і передаються тому самому guard.
Це дозволяє коректно обробляти назви з пробілами та переносами рядків.

**Результат завершального успішного запуску:** у поточному index
не знайдено шляхів, заборонених реалізованими правилами.

Цей висновок стосується лише перевіреного index. Він не поширюється
автоматично на untracked-файли, вміст конфігурацій або історичні коміти.
Помилка запуску Git має завершувати тест помилкою.

## Підсумок тестів

Команда запуску з кореня Git-репозиторію:

```powershell
dotnet test .\\tests\\SecureLab.Api.Tests --filter "FullyQualifiedName\~TrackedPathsGuardTests"
```

|Тест|Що перевіряє|Завершальний результат|
|-|-|-|
|`P\_IsAccepted`|Дозволений шаблон у P|Пройдено|
|`A\_IsRejected`|Заборонений шлях у A знайдено|Пройдено|
|`B\_IsAccepted`|У B немає заборонених шляхів|Пройдено|
|`OwnLists\_MatchPrediction`|Обидва власні набори відповідають прогнозам|Пройдено|
|`CurrentTrackedPaths\_AreAccepted`|Поточний Git index відповідає правилам|Пройдено|

**Очікуваний підсумок завершального запуску:** усього 5 тестів;
успішно 5; помилок 0; пропущено 0.

Обидва власні набори перевіряються в одному методі з `\[Fact]`,
тому рахуються як один тест. Допоміжний метод `RunGit`
окремим тестом не є.

## Історія: H1 та H2

За умовою навчального сценарію:

* H1 додає `config/reports.local.json`;
* H2 видаляє цей файл.

H1 і H2 тут позначають дані умови. Наявність саме таких комітів
у цьому репозиторії не підтверджена.

Видалення файла в H2 не прибирає його з попереднього H1.
Успішна перевірка B доводить лише відсутність забороненого шляху
в поточному наборі B. Вона не доводить відсутності історичного витоку.

Сам факт наявності шляху в старому коміті не доводить, що файл
містив справжній credential. Для такого висновку потрібні окремі докази.

### Межі перевірки історії

Повторювана команда для метаданих конкретного шляху:

```powershell
git log HEAD --format="%h %s" --name-status -- config/reports.local.json
```

Обсяг: історія, доступна з поточного HEAD, і лише зазначений шлях.
Команда показує метадані та статуси змін, не вміст файла.
Інші гілки, недоступні коміти, reflog та сторонні копії репозиторію
цією командою автоматично не охоплюються.

**Статус доказів:** Усі 5 тестів пройшли успішно. У поточному Git index не знайдено шляхів, заборонених реалізованими правилами. Команда перевірки історії не повернула записів для config/reports.local.json в історії поточного HEAD. H1 і H2 розглянуто як навчальний сценарій; їх наявність у цьому репозиторії не підтверджено.

## Статичний план реагування на підтверджений витік

### Containment

Припинити подальше потрапляння локальної конфігурації до tracked-файлів.
Використовувати безпечні шаблони та відповідні ignore-правила.
Враховувати, що `.gitignore` не прибирає вже tracked-файли з index.

### Revocation / rotation

Якщо підтверджено справжній credential, відкликати або замінити його
у відповідному сервісі. Оновити залежні конфігурації.
Видалення файла або очищення Git-історії не замінює відкликання.

### Verification

Перевірити, що старий credential більше не працює, новий працює
у потрібних компонентах, а guard відхиляє заборонені tracked-шляхи.
Перевірку вмісту й історії виконувати в явно визначених межах.

Це план дій. Фактичне відкликання, ротація або переписування історії
в межах описаних тестів не виконувалися.

## Висновок

Guard доповнено правилом для `.local.json`. Перевірки P, A, B
та двох власних наборів відповідають прогнозам. За умови завершального
успішного запуску всіх п’яти тестів поточний Git index також відповідає
реалізованим правилам назв.

Зелений B і зелений тест index не доводять відсутності секретів
у вмісті файлів або в історії. Підтверджений витік справжнього
credential потребує відкликання або ротації та подальшої перевірки.
